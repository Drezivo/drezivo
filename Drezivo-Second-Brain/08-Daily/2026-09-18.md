# 2026-09-18

Implemented the TBF-030 tenant bootstrap boundary. The authenticated owner can now complete an
eligible onboarding through one idempotent transaction that creates the tenant, default branch,
Owner membership and grant, draft storefront, trial subscription, immutable trial event, audits,
and a durable `tenant.bootstrapped` outbox event.

The bootstrap command uses a strict empty request body and requires the active Clerk organization
to match the saved onboarding. Slugs are deterministic across tenant and storefront namespaces.
Payment-pending and abandoned onboarding remain pre-tenant. The worker acknowledges the bootstrap
event without external side effects until a later consumer is introduced.

Implemented the TBF-031 actor/workspace boundary. Workspace discovery now returns only provisioned
tenants with active local membership through a narrow account-scoped database resolver. Protected
requests derive tenant authority from the Clerk token organization, resolve local membership,
active branches, selected-branch grants, subscription, and numeric entitlements under forced RLS.
Restricted and cancelled tenants reach one shared action-policy gate, while the app workspace and
branch selectors switch Clerk organization context and clear stale branch state.

PostgreSQL isolation evidence now passes against the disposable local `drezivo_test` database as
the restricted `drezivo_app` role. TBF-031 is complete.

TBF-032 is now implemented as the shared internal entitlement boundary. Active version-1 plan
resolution fails closed on invalid plan data, actor context and bootstrap reuse the same snapshot,
and tenant-lock quota guards count active physical assets and active Front Desk memberships under
the caller's transaction. Migration `0018` makes plan and entitlement data read-only to runtime
roles; TBF-040 now adds pending invitation reservations under the same tenant lock.

TBF-033 is now implemented as the final Phase 3 slice. Actor-context requests and the durable
worker share database-time trial/grace reconciliation, deterministic immutable lifecycle events,
and the existing restricted/cancelled action matrix. The Owner-only trial plan command reuses the
entitlement resolver, checks downgrade capacity, records an immutable plan-change event, and uses
transaction-aware tenant idempotency. Paid-plan changes and payment activation remain later
operator/billing work.

TBF-040 is now implemented as the first Phase 4 persistence boundary. Owner-only tenant-context
 invitation routes store only a keyed recipient digest and AES-GCM ciphertext, reserve Front Desk
 seats under the tenant lock, and write safe Clerk-dispatch outbox intents atomically. Reuse,
 resend, cancellation, and database-time expiry preserve one invitation row and release capacity
 safely; Clerk dispatch and invitation claiming remain TBF-041 and TBF-042.
