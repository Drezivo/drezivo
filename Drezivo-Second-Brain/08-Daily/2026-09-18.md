# 2026-09-18

Implemented the TBF-030 tenant bootstrap boundary. The authenticated owner can now complete an
eligible onboarding through one idempotent transaction that creates the tenant, default branch,
Owner membership and grant, draft storefront, trial subscription, immutable trial event, audits,
and a durable `tenant.bootstrapped` outbox event.

The bootstrap command uses a strict empty request body and requires the active Clerk organization
to match the saved onboarding. Slugs are deterministic across tenant and storefront namespaces.
Payment-pending and abandoned onboarding remain pre-tenant. The worker acknowledges the bootstrap
event without external side effects until a later consumer is introduced.
