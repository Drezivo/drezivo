# 2026-09-29

Implemented Calendar frontend phases FE-1 and FE-2 from
[[05-Operations/Schedule Calendar Checklist]]. The Schedule page now loads actor context,
uses the active branch timezone for API range boundaries and event grouping, and maps the
shared Calendar contract into one presentation model. Week and six-week Month views use
`GET /api/v1/calendar`; navigation refetches the visible range, overlapping Week events remain
side-by-side, and activities outside the normal visual-hour window remain visible in a separate
list. Dense responses display an explicit incomplete-range warning. The Calendar API now returns
tenant category facets and event category IDs, so the filter offers categories instead of one
option per garment and remains within the Calendar permission boundary.

Removed the Schedule page's fixed September 2026 fixtures and fabricated reservation/fitting
detail content. The Day Agenda now lists the live event projection, while production Reservation
and Fitting detail sheets remain a later phase. Hard-coded issue metrics are no longer displayed.

App typecheck and `git diff --check` passed. Calendar unit tests were not run or rewritten in this
phase; their prototype-specific assertions are scheduled to be replaced under CAL-FE-070.

consistently to Week, Month, and Day Agenda. The real day sheet now has count-bearing activity
tabs, chronological entries, previous/next-day navigation that reuses the current range when
possible, and distinct loading, retryable error, empty, and filtered-empty states.

App typecheck passed after FE-3/FE-4. Interaction tests remain scheduled for CAL-FE-070; no test
suite or browser verification was run in this implementation pass.

Updated CAL-FE-032 to use category facets from the Calendar response. Events with multiple
category-linked garments match a selected category when any associated line belongs to it.
