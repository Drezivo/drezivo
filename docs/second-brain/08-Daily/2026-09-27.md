# Catalogue UUID-only identity cleanup

The catalogue boundary now treats product, variant, and physical-asset UUIDs as the only stable
identifiers. Product-name search remains available for human discovery; product codes, variant
SKUs, and physical-asset codes are no longer accepted, generated, stored, or returned.

The forward-only `0053_remove_catalogue_codes.sql` migration drops the three columns and their
unique/search/format dependencies. This is intentionally destructive for pre-production data.
Contracts, OpenAPI, API read/write paths, reservation/fitting/storefront projections, and app
catalogue consumers were updated together. See [[Clothing Checklist]] and the canonical
[[Drezivo-Data-Model]] for the durable boundary.

Integration tests requiring PostgreSQL must be rerun after setting `TEST_DATABASE_URL`; no data
preservation or compatibility alias is intended for the removed fields.
