# 2026-10-04

## Guest reservation email verification

- Documented the planned change to allow reservations and receipt submission before email
  verification, while keeping reservation access capability-based and fitting verification intact.
- The plan calls for contract/API compatibility, optional verified private-link recovery, migration
  of per-reservation verification state, notification controls, and explicit ADR supersession.

See [[Drezivo Home]] for the project knowledge map.

## Decision update (2026-10-05)

The owner approved implementation with a broader scope than the initial proposal: remove verification
for both reservation and fitting guest flows, and send no guest-directed reservation/fitting email.
Reservation proof uses a scoped API-host HttpOnly cookie and screenshot-before-leaving prompt; queued
guest-directed email is cancelled, while owner/business notices remain. See [[Reservation Email Verification Removal Plan]]
and [ADR 0012](../../decisions/0012-storefront-guest-email-free-bookings.md). Implementation is in
the current uncommitted worktree.
