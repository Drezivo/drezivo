# 2026-09-26

## Managed PostgreSQL provider

Supabase replaced Neon as the selected managed PostgreSQL provider before Neon stored any Drezivo
data. The change keeps the existing Drizzle, `node-postgres`, SQL migration, forced-RLS, Clerk,
and S3/MinIO boundaries.

The canonical architecture and runbooks now require Supabase's Data API to remain disabled,
separate restricted API and worker roles, a direct migration connection, encrypted runtime
connections, isolated staging, and a rehearsed backup/restore path. See [[Supabase Managed PostgreSQL]]
and [[02-Architecture/Drezivo Architecture]].
